תנאי כניסה: work/05_model_comparison.md מאושר.

1. קרא את references/system-template.md.
2. שכבת החלטה: ציון ← פעולה מומלצת (מהרשימה הסגורה בקנבס) + שלושת הנימוקים המרכזיים + רמת ודאות. ציון בתחום אפור – לבדיקה ידנית.
3. ממשק: דשבורד למקבל ההחלטה (רשימת מקרים מדורגת, כרטיס מקרה עם הסבר, כפתור אישור/דחייה שנרשם).
4. API: נקודת קצה אחת שמקבלת רשומה ומחזירה ציון + המלצה + הסבר.
5. ניטור: סחיפת נתונים (PSI), ביצועים מול תוצאות בפועל, שיעור דריסות של מקבלי ההחלטה, וסף לאימון מחדש.
6. תיעוד: model card (מטרה, נתונים, מגבלות, הטיות, בעלים).
7. פלט: תיקיית system/ + סיכום להנהלה בעמוד אחד.

בסוף: הרץ את ה-API מקומית עם רשומה אחת מסט הבדיקה וודא שהתשובה כוללת ציון, פעולה, 3 נימוקים ורמת ודאות.
